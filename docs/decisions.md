## 2026-11 기술 선택
- **TypeScript + Vite, 프레임워크 없음(Vanilla).** 게임은 캔버스에 직접 그리므로 React 같은 UI 프레임워크가 필요 없음.
  Vite 는 개발 서버와 빌드(여러 파일 → 배포용 파일)를 해 주는 도구.
- **백엔드 서버 없음.** 멀티플레이를 하지 않으므로, 로그인·클라우드 저장·랭킹은 Supabase(DB + 인증)로 충분.
  랭킹 점수 검증이 필요해지면 Supabase Edge Function 으로.
- **호스팅: GitHub + Cloudflare Pages.** `main` 에 올리면 자동 빌드·배포, 무료 `*.pages.dev` 주소.
  나중에 앱은 Capacitor 로 같은 코드를 감싸서.
- **협업: 두 사람 각자의 Claude 계정**, 하나의 GitHub 저장소. 이 `CLAUDE.md` 와 `docs/` 가 두 Claude 의 공통 기억.

## 2026-11 한 파일 → 모듈 분리
- 원래 `digger-pixel.html` 한 파일(약 4600줄)을 기능별 30개 모듈로 나눔. 동작은 그대로(테스트 430여 개 통과, 브라우저 실행 확인).
- **S 객체:** 최상단 `let` 59개를 `S.xxx` 로 옮김. ES 모듈은 다른 파일의 `let` 을 바꿀 수 없기 때문.
- **실행 순서 사슬:** 각 모듈이 첫 줄에서 "바로 앞 모듈" 을 import → 원래 파일의 위→아래 실행 순서가 그대로 유지됨.
  사슬 없이 나누면 `Cannot access 'ICON' before initialization` 같은 오류가 남(실제로 겪음).
  나중에 모듈마다 "필요한 것만 import" 로 정리되면 사슬을 걷어낼 수 있음.
- **`// @ts-nocheck`:** 옮긴 파일 전부에 붙어 있음. 타입은 점진적으로.
- **테스트:** `tools/build-test-html.mjs` 가 모듈을 실행 순서대로 이어 붙여 한 HTML 로 만들고,
  `tests/smoke.cjs` 가 node 의 가짜 DOM/캔버스(`tests/harness.cjs`)에서 돌림. 그래서 최상단 이름은 겹치면 안 됨.

## 2026-11 그림 파일 관리
- 모든 그림을 `public/assets/` PNG 로 내보냄(242개) + `manifest.json`.
- 코드로 그린 그림을 먼저 만들고, PNG 를 읽으면 **같은 캔버스 객체에 덮어 그림** → 그 그림을 쓰는 모든 곳이 자동으로 바뀜.
  PNG 가 없거나 못 읽어도 게임은 코드 그림으로 정상 동작.
- 원석·주괴 아트: 레퍼런스 비교 후 **gen4 v1 세트로 임시 확정** (석탄·구리·미스릴 = F, 철·은·금 = G 덩어리,
  에메랄드·다이아·루비 = B, 주괴 5종 = 비스듬한 막대 v1). "이후에 다시 작업" 예정.
- 레퍼런스 사진의 픽셀을 그대로 베끼지는 않음(다른 게임의 그림일 수 있어서). 느낌만 참고.

## 확인 못 한 것 / 할 일 메모
- 이 프로젝트를 만든 환경에서는 npm 설치가 막혀 **`npm run dev` / `vite build` 를 직접 돌려 보지 못함.**
  대신 TypeScript 로 모듈을 변환해 Chromium 에서 실행(오류 0, PNG 적용 확인) + node 테스트로 검증.
  → 처음 `npm install && npm run dev` 했을 때 문제가 있으면 이 문서에 적고 고칠 것.
- 글꼴은 CDN(jsDelivr)에서 버전 고정으로 불러옴. 앱(Capacitor)으로 갈 때는 폰트 파일을 `public/fonts/` 에 넣어 오프라인에서도 되게 할 것.
- 아이템·레시피·업적 데이터가 아직 TS 코드 안에 있음 → JSON 으로 빼면 기획 수정이 쉬워짐.

## 2026-11 글꼴 · 마을 창 정리
- **글꼴: Neo둥근모(16·32px) + 갈무리11(12px).** 예전엔 갈무리14(15px 설계)를 9~20px 여러 크기로 써서 흐릿했음.
  Neo둥근모는 옛 한국 도트 게임 느낌이 강하고 16px에서 가장 잘 읽힘. 작은 설명 글씨만 갈무리11. 둘 다 SIL OFL(무료, 상업 이용 가능).
- **마을 창 통일:** 용광로만 HTML 창이라 모양·위치가 달랐음 → 네 탭 모두 캔버스의 같은 틀(`render/townUI.ts`)로.
  폴더 모양 탭 / 머리글(제목·돈) / 본문 / 아래 상세 칸(설명+버튼). 상점은 줄을 누르면 고르기, [구매] 버튼으로 구입(실수로 사는 것 방지).
- 상점 아래 능력치 표는 빼고(캐릭터 창 '장비' 탭에 이미 있음), 고른 아이템 설명을 보여 줌.
- 용광로 창을 열어 둔 동안에도 재련이 진행됨(진행 막대가 차오름).

## 2026-11 간판·탭 이름은 그림으로
- 건물 간판(정비소·상점·제작소·용광로·광산)과 마을 창 탭 이름(상점·제작·용광로·판매)을 글꼴로 쓰니 어색해서 **로고 PNG로 박아 둠**
  (`public/assets/signs/`). 아이콘 + 도트 글자 + 테두리. 건물 간판은 건물 도트와 같은 2배, 탭 이름은 1배로 그림.
- 글자 모양은 Noto Sans CJK KR Bold(OFL)를 안티앨리어싱 없이 찍어서 만듦 → `tools/make-signs.py`. 이후엔 PNG를 직접 손봐도 됨.
- '아이템 상점' 간판은 '상점'으로 줄임(탭 이름과 맞추고 지붕을 덜 가리게).
- PNG를 못 불러오면 예전처럼 글자로 그림.
